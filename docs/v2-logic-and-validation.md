## 产品的商业理念

研究者交付的价值是“可解释、可质疑、可更新的判断”。产品帮助初级研究者把市场现象转成经营机制，把机制转成有依据的参数，把参数转成可复核预测，再用后来的事实评价。页面数量、AI 对话次数或一份长报告都不能单独证明研究深度。

核心用户是具备财务基础的研究实习生和初级分析师。当前项目验证研究工作流，不虚构付费客户、商业收入或效率提升。

## 同一个研究对象，贯穿七个工作区

| 工作区 | 用户真正要回答的问题 | 程序处理 | 交付物 |
|---|---|---|---|
| 研究总览 | 公司靠什么赚钱？还不知道什么？ | 按研究时点读取披露与收入分组 | 业务结构、研究问题和数据缺口 |
| 财务诊断 | 增长有没有转化为利润与现金？ | 年度同比、会计勾稽、经营利润变化分解、现金转化 | 可以逐项回到来源的分析 |
| 市场与论点 | 市场变化如何影响经营？ | 保存机制、支持、反证、推翻条件、来源和关联参数 | 用户提出的可检验判断 |
| 预测实验室 | 如果这些假设成立，会怎样？ | 五年分组预测、三情景、逐年 FCFF、DCF、参数敏感性 | 完整计算明细和不可改写快照 |
| 证据与审核 | 我们知道的东西可靠吗？ | 保存口径、单位、期间、披露日期、审核状态 | 来源面板、用户审核记录 |
| 预测检验 | 当时的判断错在哪里？ | 冻结预测；后续同口径实际值匹配；绝对误差、APE、区间覆盖 | 带实际保存时间的检验记录 |
| 研究备忘录 | 最终判断是什么，为什么改了？ | 编辑、版本保存、资料更新提示、导出 | 有证据与假设的研究文件 |

### 一条真实可操作的练习路径

1. NVIDIA，研究日期 2025-03-01，读取 2025-02-26 的年度公告。
2. 核对 FY2025 收入 130,497、FY2024 收入 60,922，金额均为 USD million。
3. 拆解经营利润增加 48,481：规模、毛利率、费用三项相加；说明这只是会计分解，不自动证明市场因果。
4. 建立自己的论点。必须写反证和推翻条件，并关联模型参数；系统不自动把“竞争加剧”转成精确销量下降。
5. 调整收入分组增长与资金占用，观察五年现金流及估值。查看参数各上调 1pp 的影响，决定下一步优先核对哪类资料。
6. 填写理由并冻结模型；输入值、来源、参数、结果一起保存。
7. 在预测检验中以历史管理层指引 43,000 ±2% 为练习基准。明确这是管理层指引复盘，不是本人独立预测。
8. 导入 2025-05-28 的后续季度公告。在 2025-03-01 时仍不能看到季度实际值；把日期改到 2025-06-01，才能用 44,062 检验。绝对误差 1,062，APE 2.41%，实际值超出该指引区间。
9. 写下偏差原因需要什么证据，保存备忘录新版本。单条练习不证明长期预测能力。

## 程序怎样工作

浏览器负责展示与编辑 → 本机 HTTP API 校验请求 → SQLite 保存来源、指标、研究版本及操作记录 → 确定性 Python 引擎计算 → 返回明细 → 浏览器画图。运行时没有云模型调用、行情请求或付费 API。

- **Provenance（数据来历）**：指标保留原始来源 ID、URL、定位、披露日期和口径；模型快照复制使用的指标值与文档元数据。
- **Semantic layer（指标语义层）**：指标不是一个无单位的数字。GAAP/Non-GAAP、全年/单季、公司收入占比/市场份额分别处理；导入目前只接受明确的 USD million / GAAP / 合并口径。
- **Point-in-time（当时可得信息）**：数据层按披露日筛选，不只是界面隐藏。模型无法绕过此限制。后来做的操作记录仍展示实际保存时间，并不冒充当时已存在。
- **Human-in-the-loop（人工审核）**：初始数据全部待用户确认；点击审核保留记录。程序测试通过不等于人已核对全部原文。
- **Evaluation（检验）**：同时检验计算正确性、口径、日期边界、保存行为和用户交互，而不是只查页面是否好看。

当前数据层保存财政年度/季度标签与期间类型；尚未完整补齐每个观察值的财政期间起止日期。跨不同财年公司的同期比较因此不开放。来源摘录不是完整原文存档。

## FinRobot 的深度与我们的取舍

固定版本具有数据获取、指标处理、增长预测、同业分析、估值、敏感性和分章节研究代理。它比早期界面复杂；不能把“容易操作的界面”等同于“浅显的分析系统”。

本项目沿用模块分工思路，在确定性计算、时点控制和研究版本上另行实现。没有将多代理数量当作研究质量指标；没有复制上游计算代码到生产引擎。新代码由 AI 开发，业务选择来自用户目标，用户的审核与掌握程度需另行记录。

实际运行未改动的上游模块，合成输入结果如下（不调用 API）：

| FCF = 0、EBITDA = 100 | 与显式 FCF = 60 的估值相同，约 109.01817/股 | 不用 EBITDA 比例静默覆盖已知 0 |
| 60 FCF、10 股，WACC 从 10% 到 11% | 上游区间低值 103.39561，完整重算 95.32827 | 敏感性每格重算完整模型 |

## 实测与限制

后端测试覆盖：手算可验证的恒定现金流估值、利润桥、现金流、缺失、零值、无穷数、WACC 边界、完整敏感性重算、披露时间、审核持久化、公司隔离、快照不可覆盖、新资料更新、重复导入、指标契约、预测检验与回溯标签。16 项通过。浏览器测试验证完整研究操作链、刷新后保留、文字注入转义、D 盘导出、跨来源写入拒绝及私有路径不可访问；没有浏览器脚本错误。

布局实测：全部七个工作区在 1280 和 390 像素宽度下没有整页横向溢出；首页另测 1440 和 1920。数据表在容器内滚动，不通过隐藏内容伪装适配。

修复实际发现的问题：Windows SQLite 连接未关闭造成文件锁；日期早于披露仍返回静态收入分组；零基数利润桥除零；导入的 Non-GAAP 同名指标可能污染 GAAP 基准。浏览器导出在重复测试中提前关闭，改为服务端直接写入项目 `exports`，验证路径与内容。测试环境与用户资料库分开，测试中的“已审核”不会写入用户资料库。

尚未完成：完整三表联动、季度季节性、行业 TAM/SAM/SOM 和竞争份额数据库、同行可比性审核、真正的产业关系图、PDF 自动抽取、模型 API、多用户服务、精确字段级依赖更新、用户人工逐项审核。Adobe 未接入的现金流与资产负债数据仍为空，预测使用显式假设。不能宣称已验证企业内部经营分析。

本轮没有外部 API 调用费用；未测人工研究耗时基线，不能填写效率提升百分比。
