# Problem brief 与决策记录

目标用户：有财务基础的初级研究者、研究实习生及初级分析师。

问题：数字与结论脱离来源，行业不同却套用相同指标，假设修改难以追溯。

成功标准：能解释输入来自哪里、计算如何完成、为何修改判断；历史截止日不使用后来数据；未知信息明确保留为空。尚未经过目标用户测试，不能声称需求已验证。

## 2026-09-18 决策

用户进一步澄清：目的不是完全复现 FinRobot，而是借助其核心思路和代码实现 Research Atlas 的需求 demo。完整上游运行不再是前置关卡；原版失败日志作为参考保留。对数据适配、指标处理、确定性计算与报告模块逐项评估，只复用满足本项目需求的部分。

1. 采用 research-atlas 目录：用户背景包含两个路径，选择较新且与跨行业定位一致的名字，未创建 hardware-research-lab。
2. 网页优先，共用离线代码：适合简历链接和面试快速体验；桌面安装包暂缓，避免额外分发维护成本。公网只部署演示文件，不发布上游目录、运行日志或资料。
3. 首版以硬件、订阅软件验证差异：销量 × 单价与平均客户 × 年均收入，研究问题随模块切换。金融、医疗等只有规划，不提供错误通用估值。
4. 不急于复用 FinRobot：原版复现未成功；已发现样例口径冲突，先建立独立的期间与假设界面探索。原型不能作为上游复现产物。
5. 因 C 盘零主动写入约束，采用无依赖静态页面、内存会话和显式导出，不使用 localStorage。持久资料库下一阶段放 D 盘。

## 架构目标

Company、BusinessSegment、IndustryModule 分开建模；一个公司允许多个分部和商业模式。当前只有单分部 fixtures，不能声称多分部能力已经实现。

未来 semantic layer（语义层）统一指标定义、单位与可比性，而不是统一所有行业的计算。provenance（来源追踪）关联原文位置与每个输入；human-in-the-loop（人工参与审核）需要真实审核动作才能改变审核状态。
