更新：2026-09-18。本文件区分目标架构、已实现原型、后续开发。

V2 已新增本地资料库、真实历史披露案例和七工作区。最新已实现逻辑与验证以 [v2-logic-and-validation.md](v2-logic-and-validation.md) 为准；下文保留早期产品讨论，不作为当前功能验收表。

## 产品的核心单位是一个研究问题

用户选择公司、业务分部、商业模式和研究截至日期，提出一个可以被证据支持或反驳的问题，例如“增长来自终端需求，还是渠道增加库存？”

研究问题 → 公开资料 → 证据审核 → 业务与财务分析 → 假设 → 情景计算 → 研究判断 → 新资料触发修订。

## 1. 资料与证据

资料是整份年报、公告或业绩说明。证据是其中支持具体命题的原文或数字，带文档位置、期间、单位、口径及披露日期。AI 可建议抽取结果，必须保留候选和人工审核状态。抽取失败或来源失效不能补写为事实。

数据状态 Disclosed / Calculated / Assumed 与审核状态分别存储；模拟案例另行隔离。真实披露也可能尚未人工核对，不等于“已审核”。

## 2. 商业模式与财务分析

行业决定要问哪些问题；商业模式决定适用指标和模型；业务分部决定每组输入覆盖的范围。一家公司可以有多个行业与商业模式，不能用一个行业标签覆盖全部分部。

硬件示例：产品组合、销量、实现均价、成本、渠道库存和回款。

订阅软件示例：平均客户、合同履约、留存与扩张、收入确认、客户集中度。期末 ARR 不能直接充当全年报表收入。

财务质量关注收入增长能否转化成利润和现金，以及资金占用和会计口径；不是仅展示若干财务卡片。同行比较必须先完成指标定义和范围匹配。

## 3. 假设

每条假设包含参数、范围、依据、反证、未知项及版本。例如“销量增长 10%”必须说明原因，不能将竞品降价直接换成一个销量下调比例。

AI 负责提出可能解释或反证；研究者选择接受、修改或拒绝。只有真实发生的人工动作才能记录为审核。

## 4. 确定性计算

输入的单位、期间、口径与可用日期通过检查后才进入模型。程序执行公式，结果附公式与输入 ID。缺失不等于零。

当前仅实现两种教学模型：硬件销量 × 单价；软件平均客户 × 年均收入，以及收入 × 毛利率。成本拆分、费用、营运资金、资本支出、现金流及适用估值尚未实现。

## 5. 判断与更新

研究备忘录组织“结论—支持证据—反证—关键假设—后续观察”。报告导出是工作结果，不是整个产品的唯一功能。

目标关系：Document → Evidence → Metric / Assumption → Calculation → Claim。

新公告形成新版本，标记下游受影响的输入、假设和结论。先提示待复核，再由研究者决定是否修订；不能自动覆盖旧结论。保存研究时点快照，后披露的信息不回填到旧研究中。现有日期门控不是完整的版本数据库。

## AI、程序、人的分工

| 角色 | 工作 | 边界 |
| --- | --- | --- |
| AI | 提取候选、解释、寻找反证、草拟备忘录 | 不编造缺失数据、不执行文档指令、不自行认定审核通过 |
| 程序 | 校验、公式计算、版本与影响关系追踪 | 当前仅部分计算和会话修订已实现 |
| 研究者 | 核对来源、判断可比性、选择假设、作出结论 | 用户尚未完成的审核不能由 AI 代记 |

## 本地 Apple 风试稿

入口：`apple-study.html`。沿用用户先看 PC 本地效果再上线的偏好；生产入口与 out/ 未替换。

目标：接近桌面研究应用的清晰层级与轻量交互。移除宣传式大口号，聚焦当前公司；使用灰白背景、蓝色操作色；切换视图、图表变化、证据面板滑入都有明确对象；支持减少动态效果设置。

现有能力：两个模拟案例、不同研究问题与驱动模型、基期溯源和公式抽屉、情景修改、原因必填的修订记录、备忘录、Markdown 导出、日期限制、会话隔离、键盘导航。

未实现：真实资料导入、AI 调用、语义数据存储、自动证据影响追踪、多分部模型、完整财务质量分析、同行排名、估值和持久化。UI 试稿不改变这些事实。

## 推荐下一条完整开发链路

选择真实公开公司的一条研究问题，接入少量官方材料 → 人工核对若干核心指标 → 形成一条带依据和反证的假设 → 运行适用模型 → 输出研究备忘录 → 引入第二份材料，演示结论如何被修订。

FinRobot 的资料获取、指标处理、计算与报告模块按需评估复用，保留版本与许可；不以完整复现整个项目为前置。
